## 概述

**一句话：** 用户发帖时可以附带一次投票，用来征集意见或做评选；发起人在个人中心看统计，管理员在帖子管理里看实名明细。

中南点点目前只能发帖、评论和点赞。食堂窗口、社团招新、十佳歌手这类活动，同学只能在评论里留言，发起人要自己数票，结果也不透明。本需求让任意可发帖的用户在帖子上挂一个投票：自己设定单选或多选、最多选几项、截止时间，以及别人要不要先投票才能看结果。

普通用户没有管理端。投票统计放在个人中心「我的投票」，电脑端和手机端都要有。管理端只是管理员的额外视图：同一套统计，参与明细里多出实名信息，并可以提前结束、导出。

交互和文案以线上原型为准：[https://yml-001.github.io/zndd/](https://yml-001.github.io/zndd/)。原型用浏览器本地数据演示，正式系统按现有帖子服务实现，不要求照搬原型的存储方式。

**要点：**

- **使用人：** 可发帖的学生与教职工；发起人看自己的统计；学工管理员看实名明细
- **要解决的事：** 活动征集和评选只能靠评论，无法计票、截止和公示
- **核心指标：** 上线后 30 天内，带投票帖子的平均参与人数
- **上线时间：** 待研发评估后排期

## 问题

### 现在的情况

同学要在校园里做一次选择，只能发一条帖子，让大家在评论里回复选项。发起人数不清重复发言，截止时间靠口头约定，结果公布也没有固定位置。吐槽建议、点赞表扬、校园日常都能发帖，但没有「让大家直接选」的能力。

### 影响

学生办活动时，计票耗在评论里，结果容易有争议。管理部门如果要了解一次投票的参与情况，看不到汇总，也导不出名单。已有的帖子、消息、封禁、风险词能力都在，缺的是挂在帖子上的投票本身。

### 为什么现在做

日常运营里已经有食堂窗口、歌手评选这类需求。原型三端（电脑前台、手机端、管理端）已经把规则跑通，可以作为开发和验收的对照，不需要再单独立项做交互探索。

## 目标

### 业务目标

1. **活动能直接投票。** 发帖即可发起单选或多选，到截止时间自动停止。
2. **发起人自己能收口。** 不进入管理端，也能看到票数、趋势和参与明细，并能提前结束、导出。
3. **管理可追溯。** 管理员能按「是否含投票」筛选，查看实名参与明细，必要时提前结束。

### 用户目标

1. 发帖时用几步配好投票，而不是在正文里写「回复 1 或 2」。
2. 打开帖子就能选，选完立刻知道自己投了什么；在发起人允许的前提下看到当前结果。
3. 发起人随时知道有多少人参加、哪项领先，有新票时能被提醒。

### 明确不做

- 不把投票做成独立于帖子的活动页。
- 不让发起人看到参与者的姓名、学号、学院。
- 不改数据概览页。
- 不支持投完后改票。

---

## 用户

### 主要用户：发帖同学

在校学生或教职工，会用中南点点发校园日常、吐槽建议。办社团、问食堂、做评选时，希望一篇帖子就能收集选择。他们没有管理端账号。被封禁，或首次使用还没完善昵称和头像的人，不能发帖，也不能投票。

### 次要用户：投票发起人

上面这类用户里，发出带投票帖子的人。需要看到统计、新参与提醒、提前结束和导出。统计里只能看到昵称和头像。

### 次要用户：学工管理员

使用现有管理端。需要在帖子列表里找到投票帖，打开详情看实名明细，必要时代为结束投票并导出。管理员始终能看到票数，即使自己没投。

## 用户故事与需求

### 史诗：帖子投票

以下均为本期必须交付（P0）。工作量是建议量级，由研发最终估算。

#### 故事 1：发帖时添加投票

**用户故事：**

作为可发帖的用户，
我希望在发布或编辑帖子时附带一个投票，
以便一次把问题和选项交给同学直接选择。

**验收标准：**

- [ ] 电脑端发布页在图片上传区下方提供「添加投票」。手机端发布页、编辑页提供同样入口。
- [ ] 未添加时，帖子与现在一样发布，不产生投票数据。
- [ ] 添加后可填写：投票主题、选项、单选或多选、截止时间、结果可见性，并可移除整段投票。
- [ ] 主题必填，去首尾空格后 1–50 字。
- [ ] 选项 2–10 个。每项去首尾空格后 1–30 字，不能为空，不能与其他项重复。
- [ ] 单选时每人只能选 1 项。多选时「最多选 N 项」的 N 为 2 到选项个数（含两端）。删掉选项后，若 N 大于剩余选项数，自动降到选项数，且不低于 2。
- [ ] 截止时间可选 1 天、3 天、7 天，或自定义到分钟。提交时截止时间必须晚于当前时间。预设天数从提交时刻起算。
- [ ] 结果可见二选一：「投票后可见」或「任何人可见」。默认「投票后可见」。
- [ ] 发布校验失败时，用明确文案提示，不创建帖子。文案见附录。
- [ ] 投票主题和选项文字走现有发帖风险词检测，与标题、正文一起扫描。
- [ ] 草稿保存投票的原始填写内容，保存时不校验是否填完。从草稿继续编辑时恢复投票。从草稿发布成功后，按现有逻辑删除该草稿。
- [ ] 电脑端与手机端字段、校验、默认值一致。

**优先级：** P0
**建议工作量：** M

#### 故事 2：编辑已发出的投票

**用户故事：**

作为发起人，
我希望在还没人投票时改投票，有人投票后只改截止和可见性，
以免已投出的票对不上选项。

**验收标准：**

- [ ] 尚无人投票时，发起人可修改主题、选项、单选或多选、最多项数、截止时间、结果可见性，也可以移除投票。
- [ ] 已有至少 1 人投票后：主题和选项只读，不能增删改选项，不能切换单选或多选，不能移除投票。界面说明「已有 N 人参与，选项不可修改，只能延长截止时间」。
- [ ] 有人参与后，截止时间只能延长，不能缩短，也不能改成当前或过去。不修改截止时间时，允许只改结果可见性。
- [ ] 管理员按现有规则可编辑帖子。对投票的修改约束与发起人相同：有人参与后不能改选项、不能移除。
- [ ] 帖子被删除后，前台列表、详情、我的投票都不再展示该投票。

**优先级：** P0
**建议工作量：** S

#### 故事 3：在帖子里投票

**用户故事：**

作为读者，
我希望在帖子详情里直接选择并提交，
以便不用在评论里表明态度。

**验收标准：**

- [ ] 详情在正文图片下方、互动数据上方展示投票卡。无投票的帖子不出现该区域。
- [ ] 卡片展示：主题、规则行、选项、提交按钮。规则行示例：「单选 · 14 人参与 · 剩余 3 天 1 小时」；多选为「多选 · 最多 3 项 · 8 人参与 · 已结束」。
- [ ] 进行中且本人未投票时，可点选选项再提交。单选点另一项即替换。多选再次点击已选项即取消。已选数量达到上限后再选新项时，提示「最多只能选择 N 项」，不改变已选。
- [ ] 未选择时提交按钮不可用。提交成功提示「投票成功」，卡片变为结果态，标出「已选」。
- [ ] 每人每帖只能投一次，不能改票。再次提交提示「你已经投过票了」。
- [ ] 以下情况不能投票，并提示对应原因：账号封禁、未完善昵称或头像、帖子已删除、投票已到截止时间或已提前结束、未选择、单选却提交多项、选项不属于该投票。
- [ ] 发起人可以给自己的投票投票。
- [ ] 截止判断：当前时间达到截止时间，或存在提前结束时间，即为结束。结束后不提供选择和提交。
- [ ] 列表卡片展示标记：「投票中 · N人参与」或「投票已结束 · N人参与」。N 为参与人数，不是票数合计。
- [ ] 电脑端首页排序栏、手机端首页排序行提供「只看投票」。开启后只显示带投票的帖子（含已结束）。无结果时分别提示「暂无投票帖」。
- [ ] 热度沿用现有公式，并增加参与人数：每名参与者计 1，与浏览、点赞、评论一起参与衰减。多选不按选项数重复计热度。

**优先级：** P0
**建议工作量：** M

#### 故事 4：按规则展示结果

**用户故事：**

作为参与者或发起人，
我希望在允许查看时看到票数和占比，
以便知道当前哪项领先。

**验收标准：**

- [ ] 满足任一条件即可看结果：本人已投票、投票已结束、发起人设置为任何人可见、当前用户是发起人、当前用户是管理员。
- [ ] 不满足时，选项上不出现票数、占比和进度条，并提示「投票后可查看结果」。
- [ ] 占比 = 该选项票数 ÷ 参与人数 × 100，保留 1 位小数。参与人数为 0 时，各项为 0 票、0%。
- [ ] 多选时一名参与者可计入多个选项，各项占比之和可以超过 100%。统计页需说明「多选时占比按参与人数计算，合计可超过 100%」。
- [ ] 票数最高的选项为领先。并列时都算领先，名称用「 / 」连接。无人参与时领先为「暂无」。
- [ ] 本人选项显示「已选」。领先项在结果条上可区分。
- [ ] 剩余时间：已提前结束、已结束、剩余 X 天、剩余 X 天 Y 小时（有零头小时才写出小时）、剩余 X 小时、剩余 X 分钟（不足 1 分钟显示 1 分钟）。

**优先级：** P0
**建议工作量：** S

#### 故事 5：个人中心查看我的投票

**用户故事：**

作为普通用户，
我希望在个人中心看到我发起和我参与的投票，
以便不用进管理端也能跟踪活动。

**验收标准：**

- [ ] 电脑端：首页右侧个人卡片，「我的举报」旁增加「我的投票」，打开抽屉。
- [ ] 手机端：「我的」页列表中，「我的举报」上方增加「我的投票」，进入独立页面。
- [ ] 有未查看的新参与时给出提醒。电脑端为红点。手机端为「N 条新投票」。N 是进行中、由我发起、且自上次查看统计后新增的参与人数之和。已结束的投票不再计入。打开该投票的统计后，该投票的新增数清零。
- [ ] 两个页签：「我发起的」「我参与的」。空列表文案：「暂无投票，发帖时可以添加投票」和「暂无投票」。已删除帖子不出现。
- [ ] 「我发起的」按发帖时间从新到旧。每条展示：进行中或已结束、主题、所属帖子标题、参与人数、剩余时间或结束状态、当前或最终领先。有票时展示各选项的紧凑票数条。点击进入统计。
- [ ] 「我参与的」按本人投票时间从新到旧。展示主题、所属帖子、我选了哪些项、投票时间。已投票故可见结果：进行中显示当前领先和参与人数，已结束显示最终结果和参与人数。点击进入原帖详情。
- [ ] 同一帖若本人既是发起人又投了票，两个页签都出现。

**优先级：** P0
**建议工作量：** M

#### 故事 6：发起人查看统计、结束和导出

**用户故事：**

作为发起人，
我希望看到参与人数、趋势和名单，并能提前结束或导出，
以便向同学和部门说明结果。

**验收标准：**

- [ ] 仅发起人可打开自己的统计。其他人调用时拒绝，提示「仅发起人可查看投票明细」。管理员走管理端，不走这条个人入口。
- [ ] 电脑端用弹窗，手机端用独立页「投票统计」。
- [ ] 概要四项：参与人数；投票率；当前领先或最终领先；截止时间。已提前结束时，时间标签为「提前结束于」，否则已结束为「截止于」，进行中为「截止时间」。
- [ ] 投票率 = 参与人数 ÷ 帖子浏览量 × 100，保留 1 位小数，最高 100%。浏览量为 0 时显示 0%。
- [ ] 选项统计：票数、占比、进度条，标出已选和领先。
- [ ] 参与趋势：按自然日统计当天新增参与人数，用柱状条展示，不依赖图表库。范围从发帖日到结束日（进行中则到今天）。跨度超过 14 天时，只保留结束日前的最近 14 天（含结束日）。无人参与时显示「暂无人参与」。
- [ ] 参与明细：序号、昵称、头像、所选项（多项用顿号）、投票时间。按投票时间从新到旧。明确标注「仅发起人可见，不展示实名信息」。不得返回或展示姓名、学号、学院、手机号。
- [ ] 操作：「查看原帖」「导出投票明细」。进行中额外提供「提前结束投票」。
- [ ] 提前结束前需确认，说明结束后不能再投，参与者会收到通知。确认后状态变为已提前结束。
- [ ] 导出文件为 UTF-8 带 BOM 的 CSV，可用 Excel 直接打开中文。内容含：投票主题、参与人数、各选项票数和占比、明细（序号、昵称、所选项、投票时间）。所选项之间用中文分号。文件名包含主题前 20 字和导出日期。发起人导出的文件不含实名列。

**优先级：** P0
**建议工作量：** M

#### 故事 7：结束通知

**用户故事：**

作为参与者，
我希望投票被提前结束时收到通知，
以便去看最终结果。

**验收标准：**

- [ ] 发起人或管理员提前结束时，给每位参与者发一条现有「系统」消息：「你参与的投票「主题」已结束，快去看看结果吧」，并可跳到原帖。
- [ ] 不给操作者自己发这条消息。若管理员也投过票，管理员不会收到「你参与的投票已结束」。
- [ ] 管理员结束、且管理员不是发起人时，另给发起人发：「你发起的投票「主题」已被管理员提前结束」，可跳到原帖。
- [ ] 自然到截止时间不补发「已结束」通知。
- [ ] 消息走现有系统通知通道，出现在消息页「系统」页签。

**优先级：** P0
**建议工作量：** S

#### 故事 8：管理端查看、结束和导出

**用户故事：**

作为学工管理员，
我希望在帖子管理里筛出投票、查看实名明细并必要时结束，
以便处理异常活动。

**验收标准：**

- [ ] 帖子管理筛选增加「是否含投票」：全部、含投票、投票进行中、不含投票。「投票进行中」不含已到截止时间或已提前结束的帖。
- [ ] 表格增加「投票」列：无投票显示「—」；有投票显示「N 人参与」以及「进行中」或「已结束」。点击参与人数打开该帖详情。
- [ ] 帖子详情增加「投票信息」区块，统计内容与发起人统计一致，并标注「管理员可见实名信息」。
- [ ] 明细增加姓名、学号、学院。昵称可打开现有「发帖人实名信息」。无实名时这些字段显示「—」。
- [ ] 进行中的投票，管理员可提前结束，规则和确认与发起人相同，并触发故事 7 的通知。
- [ ] 管理员导出的 CSV 在发起人版本基础上增加姓名、学号、学院三列。
- [ ] 数据概览页本期不改。

**优先级：** P0
**建议工作量：** M

### 非功能需求

| 编号 | 类别 | 要求 | 目标 |
|------|------|------|------|
| NFR-001 | 一致性 | 电脑端、手机端、管理端对同一帖的票数、状态、可见性一致 | 任一端提交后，其他端刷新或重新进入即可看到新结果 |
| NFR-002 | 并发 | 同一用户重复提交只保留一票 | 服务端以用户 + 帖子唯一约束兜底，不依赖前端禁用按钮 |
| NFR-003 | 权限 | 非发起人、非管理员不能读取参与明细和实名 | 接口层拒绝，不只是隐藏按钮 |
| NFR-004 | 隐私 | 发起人接口响应体不含姓名、学号、学院、手机号 | 抽检接口字段 |
| NFR-005 | 性能 | 打开含投票的帖子详情、打开统计 | 投票数据随帖子返回，统计页在常规校园并发下 1 秒内可渲染 |
| NFR-006 | 兼容 | 导出的 CSV 用 Excel 打开中文不乱码 | UTF-8 BOM |
| NFR-007 | 无障碍 | 选项是按钮或带标签的表单控件，不只靠颜色区分已选和领先 | 文字上有「已选」；进行中的选择有选中态 |
| NFR-008 | 现有能力 | 不改变无投票帖子的发布、评论、点赞、举报、置顶、删除 | 回归通过 |

## 业务规则

### 数据

一条帖子最多一个投票。没有投票时该字段为空。建议字段：

| 字段 | 含义 | 约束 |
|------|------|------|
| title | 投票主题 | 1–50 字 |
| options | 选项列表 | 2–10 项，每项有稳定 id 和 1–30 字文本 |
| multi | 是否多选 | 否为单选 |
| maxSelect | 最多可选数 | 单选固定为 1；多选为 2 到选项数 |
| deadline | 截止时间 | 创建时必须晚于当前时间 |
| showBeforeVote | 未投票是否可见结果 | 真为任何人可见，假为投票后可见 |
| ballots | 选票 | 每条含用户、选项 id 列表、投票时间。同一用户至多一条 |
| closedAt | 提前结束时间 | 0 表示未提前结束 |
| seenN | 发起人已查看的参与人数 | 只用于新参与提醒 |

选项 id 在创建后保持不变。有人投票后不允许替换选项列表。

### 谁能看见结果

| 身份 | 未投票且进行中 | 已投票 | 已结束 |
|------|----------------|--------|--------|
| 路人，设置为投票后可见 | 不可见 | 可见 | 可见 |
| 路人，设置为任何人可见 | 可见 | 可见 | 可见 |
| 发起人 | 可见 | 可见 | 可见 |
| 管理员 | 可见 | 可见 | 可见 |

「可见」指票数、占比、进度条、领先项。主题、规则、选项文字、参与人数始终可见。参与人数不是结果明细。

### 结束

投票在下面任一情况结束：

- 当前时间大于或等于截止时间
- 发起人或管理员确认提前结束

结束后不能再投。自然截止不发通知。提前结束才发通知。

### 编辑矩阵

| 操作 | 无人参与 | 已有人参与 |
|------|----------|------------|
| 改主题、选项、单选或多选 | 允许 | 拒绝 |
| 移除投票 | 允许 | 拒绝，提示已有人参与 |
| 缩短截止时间 | 允许，但仍须晚于当前时间 | 拒绝 |
| 延长截止时间 | 允许 | 允许 |
| 修改结果可见性 | 允许 | 允许 |

### 统计口径

- 参与人数 = 选票条数 = 去重后的投票用户数。
- 某选项票数 = 选票中包含该选项的人数。
- 占比分母是参与人数，不是选项票数之和。
- 投票率分母是该帖浏览量，分子是参与人数，上限 100%。
- 热度只加参与人数 1 次，不按选项数相加。
- 新参与数 = 当前参与人数 − 发起人上次查看统计时的参与人数。仅统计进行中且本人发起的投票。

### 删除与封禁

- 帖子删除后，投票从所有前台入口消失。已产生的系统通知若指向该帖，沿用现有「该贴已删除」处理。
- 封禁用户不能发帖、不能投票，沿用现有封禁提示。
- 未完善资料的用户不能发帖、不能投票，沿用现有首次使用提示。
- 用户被封禁不影响其历史选票。不要求删除已经投出的票。

## 成功指标

功能全新，上线前基线为 0。下表是建议观察指标，目标值在评审时与业务确认，不作为开发完成的门槛。开发完成以验收标准为准。

**首要指标：** 上线后 30 天，带投票且未被删除的帖子，平均参与人数。

**定义：** 这些帖子的参与人数之和 ÷ 帖子数。

**建议观察：**

| 指标 | 说明 | 建议观察窗口 |
|------|------|----------------|
| 带投票帖子数 | 发布时带投票、且未删除 | 30 天 |
| 投票完成率 | 至少 1 人参与的投票帖 ÷ 全部投票帖 | 30 天 |
| 人均参与 | 首要指标 | 30 天 |
| 提前结束占比 | 提前结束次数 ÷ 已结束投票数 | 30 天 |
| 导出次数 | 发起人与管理员导出次数 | 30 天 |
| 拦截次数 | 重复投票、封禁、截止后投票被拒绝的次数 | 30 天 |

**建议埋点：**

- `vote_create`：发布成功且带投票。记录单选或多选、选项数、是否任何人可见、截止预设或自定义。
- `vote_cast`：投票成功。记录帖子、选项个数。
- `vote_cast_blocked`：被拒绝。记录原因：已投、已结束、封禁、未完善资料、超限、未选择。
- `vote_stats_view`：发起人打开统计。
- `vote_close`：提前结束。记录操作者是发起人或管理员。
- `vote_export`：导出。记录是否含实名列。

不要求本期做新的数据看板。埋点进入现有统计即可。

## 技术约束

正式系统已有帖子、评论、用户、封禁、消息和管理端。投票挂在帖子上，复用这些能力。

### 权限

- 创建、编辑、投票：沿用发帖前的「未封禁」和「已完善资料」判断。
- 提前结束、查看明细：帖子作者，或管理员角色。
- 实名字段：仅管理员角色的明细接口和导出返回。
- 作者不能通过改参数看到实名。管理端接口与个人中心接口分开，或在服务端按角色裁剪字段。

### 一致性

- 一人一票在服务端保证。前端连点、多端同时提交，最终只有一条选票。
- 选项 id 由服务端生成并持久化。前端可以临时编号，提交后以服务端 id 为准。
- 截止与提前结束的判断以服务端时间为准。

### 与现有帖子的关系

- 创建帖子的接口增加可选投票对象。不传则无投票。
- 更新帖子时：不传投票字段表示不修改投票；传空表示移除；传对象表示新建或修改。移除和修改都要执行编辑矩阵。
- 草稿中的投票允许不完整，发布时再执行全部校验。
- 风险检测文本 = 标题 + 正文 + 投票主题 + 各选项文本。
- 帖子软删除后，投票不再出现在前台查询中。

### 接口行为（能力要求，路径由研发按现有风格命名）

- 帖子详情返回投票展示数据：主题、规则、选项、本人是否已投、本人选项、是否可看结果、是否已结束、剩余或结束文案。不可看结果时，不返回各项票数和占比。
- 提交投票：入参为帖子 id 和选项 id 列表。返回更新后的展示数据。
- 我的投票：分「我发起的」「我参与的」两种列表。
- 统计明细：发起人版本与管理员版本字段不同。
- 提前结束、标记已查看、导出。导出可由接口直接返回 CSV 文件。
- 管理端帖子列表支持投票筛选，并在列表项中带参与人数和是否结束。

### 隐私

- 发起人可见：昵称、头像、所选项、投票时间。
- 管理员额外可见：姓名、学号、学院，与现有实名信息弹窗一致。
- 导出文件含个人数据，仅发起人或管理员可下载，链接不可公共访问。

### 性能与容量

按校园论坛规模设计：单帖选项不超过 10，单帖参与人数按数千量级可分页返回明细。趋势按天聚合，最多返回 14 个点。列表页不要为了投票标记再逐帖请求明细。

## 界面与交互

视觉对照原型，不另附设计稿。电脑端沿用现有帖子详情抽屉、发布页和个人抽屉。手机端沿用现有发布页、详情页和「我的」列表。投票区域用紫色系与现有蓝色主色区分，已结束改为灰色。具体色值可参考原型样式，允许在现有设计规范内微调。

### 主流程

1. 用户打开发布页，填写类型、标题、正文。
2. 点击「添加投票」，填写主题和至少两个选项，选择单选或多选、截止、可见性。
3. 发布成功后，帖子出现在列表，带「投票中 · 0人参与」。
4. 其他用户打开详情，选择并提交，看到「投票成功」。
5. 发起人在「我的投票」看到新增提醒，打开统计查看票数和名单。
6. 到截止时间后，详情变为已结束，不能再投。或由发起人、管理员提前结束，参与者收到系统消息。

### 发布页

- 入口文案：「添加投票」，副文案「征集意见、评选活动，让大家直接投票」。
- 编辑区标题为「投票」，可「移除投票」。
- 选项带序号，至少两项时删除按钮不可用，满 10 项时不显示添加。
- 多选时在单选/多选切换旁显示「最多选 N 项」。
- 自定义截止使用日期时间控件。下方提示「将于 yyyy-mm-dd hh:mm 截止」。
- 手机端字段与电脑端相同，宽度适配 390 宽屏幕，底部发布栏不被编辑区挡住。

### 详情投票卡

- 进行中：标签「投票」，选项为可选行，底部为已选提示和「投票」按钮。
- 发起人额外看到「查看统计」（有新增时带数字）和「结束投票」。
- 已投票或已结束：选项变为结果条，不再显示提交。已投票时提示投票时间。已结束时提示「投票已结束，共 N 人参与」。
- 已结束的卡片为灰色标签「投票」。

### 我的投票

- 页签显示数量，例如「我发起的 2」「我参与的 1」。
- 发起人页签说明：可查看票数、趋势和明细，也可提前结束或导出。
- 参与者页签说明：点击回到原帖查看结果。
- 统计底部操作右对齐。手机端操作按钮可换行，宽度足够点击。

### 管理端

- 筛选项名：「是否含投票」。
- 详情区块标题：「投票信息」。
- 实名列：姓名、学号、学院。昵称按钮打开现有实名弹窗。
- 提前结束和导出放在统计区块内，不替换帖子原有的置顶、编辑、删除。

### 异常与空状态

| 场景 | 表现 |
|------|------|
| 只看投票但没有投票帖 | 「暂无投票帖」 |
| 统计尚无人参与 | 趋势区「暂无人参与」；明细「暂无人参与」；领先「暂无」 |
| 非发起人打开统计 | 「仅发起人可查看投票明细」 |
| 帖子已删除 | 沿用「帖子不存在或已删除」或「该贴已删除。」 |

### 响应

- 手机端以 390×844 为验收宽度，投票卡、统计表、发布编辑区不横向撑破页面。明细表允许横向滚动。
- 电脑端以 1440 宽为验收宽度。统计弹窗在一屏内可滚动看完趋势和明细。

## 风险

| 风险 | 影响 | 可能性 | 应对 |
|------|------|--------|------|
| 发起人接口带出实名字段 | 隐私泄露 | 中 | 服务端按角色裁剪；测试用非管理员账号抓包 |
| 只在前端防重复投票 | 一人多票 | 中 | 数据库唯一约束：帖子 + 用户 |
| 截止时间用手机本地时间 | 可提前或延后投票 | 中 | 以服务端时间判断结束 |
| 有人参与后仍能改选项 | 历史票无法对应 | 低 | 服务端拒绝变更选项 id 与文本 |
| 多选占比被理解成相加应为 100% | 结果争议 | 中 | 界面写明按参与人数计算 |
| 导出文件被转发 | 名单外流 | 中 | 仅授权用户可下载；发起人文件不含实名 |

若评审否定「发起人投票前可见结果」或「发起人可以给自己投票」，只改可见性和是否允许作者投票两条规则，其余统计口径不变。

### 名词

- **参与人数：** 投过票的用户数。一名多选用户只算 1 人。
- **票数：** 某个选项被选中的次数。
- **投票后可见：** 未投票的普通用户看不到各项票数；投票后、截止后、发起人和管理员不受限。
- **任何人可见：** 未投票也能看到各项票数。
- **提前结束：** 在截止时间之前由发起人或管理员终止。
- **新参与：** 发起人上次查看统计之后新增的参与人数，只统计进行中的、本人发起的投票。
